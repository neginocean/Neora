# تکمیل قرارداد قیمت و QA زندهٔ Core — ۲۰۲۶-۱۰-۲۴

## نتیجه

قرارداد قیمت با تصمیم کاربر نهایی شد: تومان، عدد صحیح بدون اعشار. تست‌های PHPUnit، تست روی WordPress و پایگاه دادهٔ واقعی، و HTTP عمومی موفق‌اند. تأیید بصری فرم‌ها و ورود مرورگر هنوز انجام نشده است؛ ادعای آماده‌بودن کامل UI نمی‌شود.

## تغییرات محصول

تنها فایل اجرایی تغییرکرده در این مرحله `src/Modules/Services/ServicesModule.php` است:

- خط 212: عنوان قیمت شامل واحد tomans؛ راهنمای بدون اعشار/جداکننده و `inputmode=numeric`.
- خط 219: REST schema مقدار را به رشتهٔ رقم‌های لاتین/فارسی/عربی، یا رشتهٔ خالی محدود می‌کند؛ context خصوصی edit حفظ شده است. عدد JSON باید به‌صورت رشته ارسال شود؛ مثلاً `"1500000"`.
- خط 292: اتصال توضیح هر فیلد به input با `aria-describedby` و نمایش متن راهنما.
- خط 348: فیلد قیمت نامعتبر از ذخیره کنار گذاشته می‌شود؛ مقدار قبلی حذف یا به مقدار دیگری تبدیل نمی‌شود. کد معتبر خدمات همچنان ذخیره می‌شود. redirect حاوی نشانگر اعلان خطاست.
- خط 362: `sanitize_price()` رقم‌ها را به ASCII تبدیل، صفرهای ابتدایی را حذف و عدد صفر را حفظ می‌کند. تبدیل به int انجام نمی‌شود تا عددهای بزرگ سرریز نشوند. ورودی نامعتبر null و ورودی خالی رشتهٔ خالی برمی‌گرداند.
- خط 382: اعلان ترجمه‌پذیر فقط در صفحهٔ Service و برای کاربر دارای مجوز edit_posts نمایش داده می‌شود.

پاک‌کردن قیمت در فرم، ردیف آن را حذف می‌کند؛ مقدار صفر ذخیره می‌شود. REST مقدار نامعتبر را با 400 رد می‌کند؛ null ردیف را حذف می‌کند. قرارداد قبلی رشتهٔ خالی در REST تغییر نکرده است.

هیچ migration یا تبدیل ریال به تومان روی داده‌های قبلی اجرا نشد. قیمت‌های قدیمی که دارای جداکننده/اعشار هستند خودکار بازنویسی نمی‌شوند؛ ویرایش معتبر بعدی لازم است. نام meta key و نوع string برای سازگاری حفظ شدند. وابستگی تازه، تغییر vendor یا تغییر WordPress core وجود ندارد.

## نحوهٔ اجرای QA زنده و حفظ داده

اسکریپت‌های QA خارج از web root و فقط قابل اجرا با CLI هستند. پیش از نوشتن، تنها فعال‌بودن Neora Core، نبود object cache خارجی و InnoDB بودن جدول‌ها بررسی شد. دو نوشتهٔ موقت Service و Portfolio داخل START TRANSACTION ساخته شدند؛ فقط همان fixtureها هدف ذخیره بودند. در پایان ROLLBACK انجام شد و نبود نوشته‌های موقت با SQL مستقیم تأیید شد. rewrite_rules و active_plugins با مقدار پیش از آزمون یکسان بودند. auto-increment ممکن است جلو برود؛ ROLLBACK شمارهٔ تخصیص‌یافته را بازنمی‌گرداند.

نقش‌های موجود با `wp_set_current_user` در همان فرایند PHP انتخاب شدند. به حساب‌ها login نشد، credential ساخته نشد و role ذخیره‌شده تغییر نکرد. برای Author که حساب موجود نداشت، capabilityهای نقش فقط روی شیء WP_User در حافظه تنظیم شدند و ثابت‌ماندن نقش ذخیره‌شده بررسی شد. این تست مجوزها را می‌سنجد، نه فرایند authentication مرورگر.

callbackهای Bootstrap مستقیماً اجرا شدند؛ وضعیت فعال‌بودن افزونه در سایت تغییر نکرد. hard flush با filter غیرفعال شد تا هیچ فایل پیکربندی وب‌سرور نوشته نشود؛ قواعد داخل پایگاه داده در همان تراکنش حذف/بازسازی و سپس rollback شدند.

## موانع اولیه و وضعیت باقی‌مانده

- اتصال HTTP ابتدا برقرار نبود؛ پس از پاسخ کاربر، سایت در آدرس اعلام‌شده پاسخ داد.
- PHP CLI ابتدا mysqli را بارگذاری نمی‌کرد و سپس پورت پیش‌فرض پایگاه داده نادرست بود. با آرگومان‌های همان فرمان، mysqli و پورت صحیح تنظیم شدند. هشدار اتصال اولیه در debug.log باقی است و با failure افزونه اشتباه نشود.
- اجرای فایل PowerShell به‌دلیل Execution Policy رد شد؛ تنظیم امنیتی عوض نشد و آزمون HTTP با اسکریپت PHP اجرا شد.
- ابزار node_repl و ابزار کشف ابزار برای راه‌اندازی Chrome/Computer Use در این نوبت در دسترس نبودند. مرورگر از مسیر جایگزین کنترل نشد.
- بررسی بصری meta boxها، اعلان خطا، چیدمان RTL/LTR، و گردش ورود/ذخیرهٔ واقعی با session/cookie مرورگر باقی است.
